## Commands

```bash
pnpm dev          # dev server on http://localhost:3000
pnpm build        # production build
pnpm test         # run vitest tests
pnpm check        # biome lint + format check (run before committing)
pnpm lint         # biome lint only
pnpm format       # biome format only
pnpm add:component  # add a shadcn component: pnpm add:component button
```

Docker (dev):
```bash
pnpm docker:dev   # build + run via docker compose with .env.local
pnpm docker:stop  # stop containers
```

- `API_BASE_URL` — used by the server at runtime (same default)

## Architecture

**Framework**: TanStack Start (SSR React framework on top of TanStack Router + Nitro). Not Next.js — no `pages/` router, no `getServerSideProps`.

**Folder structure** follows Feature-Sliced Design:
- `src/shared/` — HTTP clients, UI primitives, store, utilities used everywhere
- `src/entities/` — domain models + their read-only query hooks (e.g. `entities/product`, `entities/order`)
- `src/features/` — user-facing feature slices with `api/`, `lib/`, `model/`, `ui/` subdirectories
- `src/widgets/` — composed UI blocks that combine multiple features
- `src/pages/` — page-level components that assemble widgets and features
- `src/routes/` — TanStack Router file-based routes (auto-generates `routeTree.gen.ts` — do not edit)

### Routing

Routes live in `src/routes/`. The route tree is auto-generated; never edit `routeTree.gen.ts` by hand.

- `__root.tsx` — root route, resolves `authUser` via `authUserQueryOptions()` and puts it in router context
- `_admin.tsx` — layout route for all `/dashboard`, `/orders`, `/menu`, etc. pages; redirects to `/auth/sign-in` if unauthenticated, and to business setup if `authUser.hasBusiness === false`
- `_admin/` subdirectory — individual admin pages
- `auth/` — sign-in, sign-up
- `customer/` — customer-facing menu (QR flow)

All route files export `errorComponent: ({ error }) => <ErrorBoundary error={error} />`.

### HTTP Clients

Two separate ky instances:

- **`clientApiInstance`** (`src/shared/api/client-instance.ts`) — browser-only, uses `VITE_API_BASE_URL`, sends cookies via `credentials: 'include'`
- **`serverApiInstance`** (`src/shared/api/server-instance.ts`) — SSR only, uses `API_BASE_URL`, forwards the incoming request's `cookie` header to the backend

Auth is cookie-based. Server functions use `serverApiInstance` + `forwardCookies()` to propagate Set-Cookie headers back to the browser.

### Auth Flow

1. Root `beforeLoad` always calls `authUserQueryOptions()` (a server fn hitting `GET /auth/me`)
2. Result is placed in router context as `context.authUser`
3. `_admin` layout `beforeLoad` reads `context.authUser` to gate access
4. Auth state lives in TanStack Query cache (`queryKey: ['me']`); Zustand is not used for auth

### Active Business

`useActiveBusinessStore` (Zustand + localStorage key `active-business`) persists `{ id, name }` of the currently selected business across page loads. The admin sidebar renders a business switcher that writes to this store.

### Forms

All forms use `react-hook-form` + `zodResolver`. Schemas live in `features/<slice>/lib/schemas/`. Follow the existing pattern: one schema file per form, export both the schema and its inferred type.

### Linting / Formatting

Biome (not ESLint/Prettier). Config in `biome.json`. Key rules:
- Single quotes, 2-space indent, 100-char line width, no semicolons
- `noExplicitAny` is an error — use proper types
- `noUnusedImports` / `noUnusedVariables` are errors
- `src/routeTree.gen.ts` and `src/paraglide/` are excluded from linting

### TanStack Query Defaults

Configured in `src/integrations/tanstack-query/root-provider.tsx`:
- `staleTime: 5min`, `gcTime: 10min`, `retry: 1`, `refetchOnWindowFocus: false`
- Mutations have `retry: 0`

### UI Components

Shadcn components are in `src/components/ui/`. Add new ones with `pnpm add:component <name>`. Custom shared UI (modals, error boundaries, loading effects) lives in `src/shared/ui/`.

Toast notifications use `sonner` — import `showError` / `showSuccess` from `#/shared/libs/hooks/toast.ts`.

### Path Aliases

Both `#/*` and `@/*` resolve to `src/*`. Prefer `#/` (used throughout the codebase).

### i18n

ParaglideJS (inlang). Messages in `project.inlang/messages/`. The `src/paraglide/` output is auto-generated by the Vite plugin — do not edit.
